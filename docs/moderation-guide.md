# 食堂夯榜审核指南

首版使用 Supabase 控制台审核，不需要额外管理后台。

## 每日审核流程

1. 打开 Supabase 项目。
2. 进入 `Table Editor > reviews`。
3. 筛选 `status = pending`，按 `created_at` 从早到晚处理。
4. 核对文字，再到 `Storage > food-photos` 按 `image_path` 查看照片。
5. 合格内容将 `status` 改为 `approved`；不合格改为 `rejected`。
6. 进入 `Table Editor > comments`，用相同方式处理待审核评论。

建议每天固定检查两次，例如午饭后和晚饭后。

## 可以通过

- 清楚展示食物，基本看不出同学的正脸。
- 楼层、档口、菜名和价格大致可信。
- 描述个人真实体验，可以批评口味、分量和排队情况。
- 使用玩笑语气，但没有针对具体个人进行攻击。

## 应当拒绝

- 清晰人脸、手机号、微信号、二维码或其他个人信息。
- 商业广告、代购、拉群或无关内容。
- 辱骂、歧视、造谣，或直接攻击食堂工作人员个人。
- 明显盗用网图、重复刷屏或与食堂无关的图片。
- 声称食品安全事故但没有基本事实信息。此类内容应先私下核实，必要时引导投稿人联系学校正式渠道。

## 审核原则

- 允许真实差评，不因评分为“拉”就拒绝。
- 只审核内容是否合规，不替食堂判断观点是否“正确”。
- 不公开投稿人的匿名用户 ID。
- 有争议时先保持 `pending`，不要急着通过。

## 每周维护

- 检查 `rejected` 投稿对应图片，确认无保留价值后在 Storage 中删除，节省免费额度。
- 查看一周内各楼层投稿量，避免首页长期被某一层占满。
- 记录用户最常遇到的失败原因，再决定是否修改表单文案。
